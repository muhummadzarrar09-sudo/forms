# Forensic Visual UI Audit — 2026-08-06

**Scope:** visual design only — color, type, spacing, layering, imagery, responsive composition, component states, motion, branding, and touch sizing. Functional, data, and security behavior were not scored except where it changes a visual state.

**Method:** complete source and rendered-CSS inventory of the active route graph. I booted the current Next app locally and inspected the emitted CSS as well as every JSX branch for the routes and components below. API-backed authenticated data was not available in the checkout, so populated/empty/error branches were audited from their actual render implementations rather than invented fixture content. This is not a sample audit: all current routes, all live feature components, all 16 respondent question types, their builder counterparts, and every live shared UI primitive are included in the score inventory.

**WCAG convention:** normal text requires **4.5:1**, large text and meaningful graphical controls/icons require **3:1**. Opacity values are composited over the rendered surface before calculating a ratio.

## Systemic patterns

1. **The most severe defect is not one color; it is uncontrolled derivation.** Four user-configured form colors are treated as complete themes, then reused with arbitrary alpha values, static red/green/blue additions, image overlays, and card surfaces. The inspector checks only two pairs and lets failures ship.
2. **The creator shell has no deliberate palette architecture.** It starts as neutral grayscale, then each feature brings its own saturated accents. Dashboard KPIs, template colors, workspaces, tags, charts, Google Sheets, scoring, and public form themes do not share a semantic or proportional system.
3. **The project straddles two token eras.** Global tokens are OKLCH, but several utilities/chart declarations still assume HSL channel tokens. This is a visible CSS correctness problem, not just code cleanup.
4. **Readability is repeatedly sacrificed for “subtle.”** The same low-opacity treatment appears in public instructions, metadata, hints, placeholders, dashboard detail, builder fields, response annotations, and footer attribution. It is systemic rather than intentional hierarchy.
5. **Desktop hover is standing in for state design.** Form cards, workspace controls, option deletion, outline actions, and compact controls hide or shrink actions instead of providing a stable touch/focus/pressed system.
6. **There are multiple competing visual languages.** The calm black-and-white shell, Typeform-inspired public filler, rainbow data graphics, emoji type picker, neon/dark/warm public themes, ambient dotted/grid/noise patterns, and multiple motion styles make the product read as assembled rather than art-directed.
7. **Dark mode is tokenized at the base but not completed at the component edge.** Core surfaces are strong, while semantic overrides, custom light tints, black overlays, and image borders leak light-mode assumptions.

## Prioritized fix order

1. **Blocker — repair the color-token pipeline.** Replace every `hsl(var(--token))` use that receives an OKLCH value, including SVG charts, gradients, grid/dot textures, scrollbar, and blank template swatches. Verify emitted CSS and chart screenshots in both modes.
2. **Blocker — make public forms AA by construction.** Correct the six failing presets; derive and validate secondary/tertiary/placeholder/border/required/focus colors; expose exact ratios; reject or gate invalid custom themes at save/publish.
