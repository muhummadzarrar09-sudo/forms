# Forensic backend and database audit — 2026-08-06

**Scope:** all tracked server/API source, Prisma schema and SQL migrations, auth/session code, deployment scripts/configuration, current public GitHub history metadata, dependency audit results, and all backend-facing tests. This audit did **not** connect to a live Supabase/Postgres project or inspect real user data.

**Evidence limits that are themselves findings:** no local `.env` or runtime DB credentials were present; Docker is unavailable; the local Git clone is shallow. The repository has no Supabase CLI/config/migration directory, no SQL RLS policy artifact, and no storage/Edge Function source. GitHub's API was used only to confirm historical `.env` commit metadata, never to print credential values.

## Systemic patterns

1. **Database security is application convention, not database enforcement.** Every owner check is implemented in TypeScript/Prisma; no RLS or policy source exists, and the documented runtime DB role is a direct Supabase Postgres connection. This becomes critical alongside publicly reachable historical DB credentials.
2. **The public response path has strong local validation but no durable respondent identity/idempotency model.** Hashing partial draft tokens and advisory locks are good improvements; full submissions can still replay, and a post-commit integration failure tells the client to retry a response that already exists.
3. **Schema history is not reproducible.** The current Prisma schema, partial post-baseline SQL migrations, `db push` deployment guidance, and legacy SQLite packaging scripts describe incompatible production states.
4. **Retention/deletion semantics are inconsistent.** Archive does not close public forms; question replacement destroys response history; owner deletes are permanent; respondents have no completed-response deletion path; cron/retention only exists if an undocumented external scheduler is actually configured.
5. **Operational guarantees are documented, not provisioned.** Cron, backup/PITR, monitoring, secret rotation, migration baseline, and deployment environment separation have no checked-in enforcement/evidence.
6. **The test suite demonstrates intent rather than release proof.** Basic validation/ownership tests exist, but current E2E JWT fixtures and Prisma generation are broken in this checkout and key adversarial paths are not covered.

## Security-first prioritized fix order

1. **Immediately rotate and revoke historic secrets, then rewrite public Git history.** Treat database access and every JWT as compromised until rotation/session invalidation/history cleanup are independently verified.
2. **Establish database access control before adding users.** Export the live Supabase schema, enable/force RLS or intentionally create a restricted Prisma runtime role, write policies for every table, storage bucket, auth schema interaction, and Realtime publication, then prove them with two-user SQL/API tests.
3. **Stop duplicate and falsely failed public submissions.** Add response idempotency/finalization credentials, catch post-commit integration failures, and harden Google outbox claiming/recovery before accepting production responses.
4. **Repair public data exposure and lifecycle rules.** Replace the public serialization DTO, make archive close every public path, define respondent deletion/retention, and remove scoring/hidden defaults from public payloads.
5. **Create one reproducible PostgreSQL release path.** Baseline migrations, eliminate SQLite packaging scripts and production `db push`, align schema/indexes/migrations, and test empty/staging/prod migration paths under change control.
6. **Harden sessions and credentials.** Set explicit JWT/session expiry, server-side logout revocation, immediate reset invalidation, strict/breached-password policy, durable registration/auth throttling, and safe OAuth state binding.
7. **Fix data-integrity constraints.** Enforce form/question/answer relationships, types/statuses/orders, JSON structure, and non-destructive question evolution; add optimistic concurrency for creator writes.
8. **Provision operations as code.** Declarative cron, queue monitoring, rate-bucket cleanup indexing, backup/PITR and restore drills, structured/redacted logs, alerting, and environment separation come before scale.
9. **Patch dependencies and make tests credible.** Upgrade vulnerable production packages, repair Prisma/JWT test fixtures, run dependency audit/migration/RLS/race tests in CI, and block deploys on failures.
